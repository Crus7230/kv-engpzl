# 학습 진행·도움 설계

## 1. 목적

이 문서는 7리전·420스테이지 캠페인을 단순한 문제 순서가 아니라 다음 구조를 갖는 학습 경로로 만들기 위한 기준을 정의한다.

`선수개념 확인 → 개념 소개 → 안내 연습 → 독립 연습 → 변형 → 전이 → 확인 → 지연 복습`

적용 범위는 다음과 같다.

- 스테이지별 학습 역할과 선수개념
- 단계형 힌트와 오개념 피드백
- 정답 후 풀이 해설
- 완료와 숙련을 분리한 진행 상태
- 다음 스테이지를 막지 않는 소프트 해금
- 간격 복습과 지원 필요 사용자 보정
- FHD 스마트폰 3열 화면 안에서의 학습 UI
- 학습 효과를 판단하기 위한 측정 지표

난도 축과 420개 스테이지의 현재 구성은 [REGIONAL_STAGE_CURRICULUM.md](REGIONAL_STAGE_CURRICULUM.md), 보드 난도와 실패 보정의 기존 기준은 [STAGE_DIFFICULTY_DESIGN.md](STAGE_DIFFICULTY_DESIGN.md)를 함께 따른다.

## 2. 현재 상태와 주장 경계

현재 C01~C03 코어 210개는 제목, `skillId`, 대표 문제·정답식, `M/B/C/R`, `W/P/L`을 가진 설계 슬롯이다. C04~C06 210개는 각 코어 문제를 어느 간격에 어떤 학습·보드 역할로 다시 만날지 정한 source-linked 슬롯이다. 420개 모두 콘텐츠 상태는 `planned`이며 실제 문장, 토큰 manifest, 개념 설명, 스테이지별 힌트, 오개념 규칙과 검증된 보드 fixture는 아직 없다. 특히 C04~C06은 새 숫자·문맥·표현이 작성되지 않아 학습 상태가 전부 `requiresRevision`이다.

따라서 현재 상태에서 주장할 수 있는 범위는 다음과 같다.

- 리전별 주제와 대략적인 난도 순서가 구성되어 있다.
- 일부 챕터는 단순 문제에서 혼합·전이 문제로 이어지는 기본 흐름이 있다.
- 프로토타입에는 관찰→관계→부분식의 타입 있는 3단계 힌트, 오류 범주별 피드백, 2단계 풀이 해설과 전이 문제가 작성되어 있다.
- 수학 난도와 발굴 보드 난도를 분리해 조정할 기반이 있다.
- 코어 210개에는 10단계 학습 역할이 있고, 추가 210개에는 원본·재출현 종류·카탈로그 간격·보드 효과 역할이 정의되어 있다.
- 420개 stage에는 재사용 가능한 `primarySkillId`, 선수·복습 개념과 지역 안 다음 stage 링크가 정의되어 있다.
- 완료 시 다음 stage를 열고, 도움 수준에 따라 복습 티켓을 만드는 순수 Dart 판정 엔진이 있다.

현재 상태에서 주장할 수 없는 범위는 다음과 같다.

- 플레이하면 해당 개념을 이해하거나 숙달한다.
- 앞 스테이지에서 배운 개념이 다음 스테이지로 전이된다.
- 한 번 맞힌 결과가 장기 기억이나 다른 문맥에서의 성공을 뜻한다.
- 별, 완료율, 이동 수가 학습 숙련도를 직접 나타낸다.
- 420개 전체에 실제 설명·힌트·복습이 제공된다.
- 월드맵·저장소·완료 화면에서 다음 stage 해금과 복습 큐가 실제로 동작한다.

앱에서 “학습 효과가 있다”고 표현하려면 실제 문제 제작, 콘텐츠 검수, 독립 성공과 지연 복습 측정, 대표 사용자 검증이 선행되어야 한다. 엔진 테스트와 카탈로그 정적 검증만으로 학습 효과를 입증하지 않는다.

## 3. 핵심 원칙

### 3.1 완료, 게임 성과, 학습 숙련을 분리한다

- `completion`: 보드와 수식을 포함한 스테이지를 끝냈는가
- `gamePerformance`: 이동 수, 경로 힌트, 탐색 별과 같은 게임 성과
- `learningEvidence`: 어떤 개념을 어떤 도움 수준에서 맞혔는가
- `mastery`: 다른 숫자·문맥과 지연 복습에서도 독립적으로 성공했는가

완료 별과 탐색 별은 게임 보상에 사용한다. 학습 숙련은 별과 별도의 데이터로 관리한다. 보드 실패는 수학 숙련을 낮추지 않으며, 읽어주기·큰 글자·색각 보정과 같은 접근성 지원은 독립 성공을 훼손하지 않는다.

### 3.2 `skillId`는 재사용 가능한 개념 단위여야 한다

현재처럼 `intro`, `transfer`, `review`, `mastery`를 서로 다른 `skillId`로 만들면 같은 개념의 학습 증거를 합칠 수 없다. 개념과 문제 역할을 분리한다.

예시는 다음과 같다.

```text
primarySkillId: pattern.additive.next
instructionalRole: nearTransfer
variantId: forest.sequence.step-4
```

하나의 스테이지에는 대표 개념 하나와 필요하면 복습 개념을 별도로 기록한다.

- `primarySkillId`: 새로 배우거나 주로 평가하는 개념
- `prerequisiteSkillIds`: 시작 전에 필요한 개념
- `reinforcedSkillIds`: 함께 복습하지만 주 평가 대상은 아닌 개념
- `variantId`: 숫자, 상황, 표현과 문제 형식의 변형

### 3.3 새 수학 개념과 새 보드 규칙을 동시에 가르치지 않는다

새 수학 개념을 소개할 때는 B0~B1과 익숙한 발굴 규칙을 사용한다. B3·B4 같은 새 보드 규칙을 소개할 때는 이미 독립 성공이 확인된 수학 개념을 사용한다.

단순히 M과 B 수치가 동시에 오르지 않는지만 검사하지 않는다. `instructionalRole == introduce`와 보드 규칙의 최초 도입 여부도 검증한다.

## 4. 챕터별 10스테이지 학습 루프

모든 챕터를 같은 문제 유형으로 채울 필요는 없지만, 10개 슬롯의 학습 역할은 다음 루프를 기본값으로 사용한다.

| 스테이지 | 역할 | 학습 목적 | 도움 원칙 |
| --- | --- | --- | --- |
| 1 | 선수개념 확인 | 이전 개념을 짧게 재인출하고 진입 수준 확인 | 실패해도 막지 않고 브리지 설명 제안 |
| 2 | 개념 소개 | 그림·조작·문장·식을 연결한 새 개념 설명 | 낮은 보드 난도, 개념 카드 제공 |
| 3 | 안내 연습 | 수량과 관계를 화면 안내에 따라 식으로 옮김 | 3단계 힌트와 슬롯 강조 사용 가능 |
| 4 | 독립 연습 | 같은 구조를 다른 숫자로 도움 없이 해결 | 첫 독립 성공 후보 |
| 5 | 가까운 변형 | 문장 명사, 수 배치 또는 표현 형식을 변경 | 답식 구조는 유지 |
| 6 | 간격 복습 | 앞 챕터 개념을 재인출하거나 익숙한 수학으로 새 보드 규칙 소개 | 주 개념과 보드 신규 규칙을 분리 |
| 7 | 표현 전이 | 그림, 표, 수직선, 도형 등 다른 표현으로 같은 관계 해결 | 두 번째 독립 성공 후보 |
| 8 | 먼 전이·혼합 | 새 상황에서 선수개념과 주 개념을 함께 적용 | 정답식이 아닌 관계 선택을 평가 |
| 9 | 누적 확인 | 챕터 핵심 개념을 섞어 취약 지점 확인 | 결과에 따라 짧은 재학습 분기 |
| 10 | 챕터 관문 | 새 규칙 없이 독립적으로 핵심 관계 확인 | 도움 완료도 허용하되 복습 상태 기록 |

모든 챕터가 새 개념 하나만 다루지는 않는다. 두 개념 묶음이 필요하면 `2~5`와 `6~9`를 각각 작은 학습 루프로 구성하고, 10번에서 두 개념을 구별·결합하게 한다. 서로 관계없는 개념을 한 번씩 나열하는 구성은 사용하지 않는다.

지역의 C01~C03은 개념을 배우는 코어 루프다. C04는 같은 지역의 앞 문제를 다시 꺼내는 나선 복습, C05는 익숙한 수학으로 새 보드 효과를 소개하거나 기존 효과를 재학습·조합하는 루프, C06은 장기 유지와 이전 지역 전이를 확인하는 루프다. 이 210개는 고정 캠페인 stage이며, 플레이 결과에 따라 추가되는 적응형 복습 ticket과 구분한다.

## 5. 스테이지 학습 메타데이터

다음 구조는 향후 Dart 모델과 콘텐츠 manifest에 필요한 논리 필드다. 실제 이름은 구현 시 주변 코드 규칙에 맞춰 조정할 수 있지만 의미는 유지한다.

```dart
enum StageLearningRole {
  prerequisiteCheck,
  introduce,
  guidedPractice,
  independentPractice,
  nearTransfer,
  spacedReview,
  representationTransfer,
  farTransfer,
  cumulativeReview,
  checkpoint,
}

class StageLearningPlan {
  String primarySkillId;
  Set<String> prerequisiteSkillIds;
  Set<String> reinforcedSkillIds;
  String variantId;
  StageLearningRole role;

  String learningObjective;
  Set<String> representationIds;
  List<TypedHintStep> hintSteps;
  List<String> misconceptionRuleIds;
  String explanationId;
  MasteryCriteria masteryCriteria;
}
```

필수 필드는 다음과 같다.

- `learningObjective`: 사용자가 무엇을 이해하고 할 수 있어야 하는지 한 문장으로 표현
- `representationIds`: 묶음 그림, 수직선, 시계, 단위 눈금, 도형, 비율표 등 의미 표현
- `masteryCriteria`: 독립 성공 횟수, 허용 도움, 필요한 전이·복습 조건
- `misconceptionRuleIds`: 이 개념에서 구분할 수 있는 대표 오개념
- `explanationId`: 정답 계산뿐 아니라 문장과 식의 대응 이유를 설명하는 콘텐츠
- `contentVersion`: 학습 증거가 어느 버전의 문제에서 수집됐는지 구분

validator는 최소한 다음을 확인해야 한다.

1. `introduce` 이전에 선수개념이 존재하거나 진단·브리지 경로가 있다.
2. 새 개념마다 소개, 안내 연습, 독립 연습, 전이, 확인 역할이 있다.
3. 같은 `primarySkillId`에 서로 다른 `variantId`가 최소 두 개 있다.
4. 체크포인트 이전에 독립 성공 기회가 최소 두 번 있다.
5. 새 수학 개념과 새 보드 규칙이 같은 스테이지에서 동시에 도입되지 않는다.
6. 모든 새 개념 스테이지에 3단계 힌트, 오개념 규칙과 풀이 해설이 있다.
7. 챕터 관문이 해당 챕터의 핵심 개념을 실제로 평가한다.
8. 지연 복습 대상과 복습 시점이 정의되어 있다.

## 6. 타입이 있는 3단계 힌트

힌트는 임의의 문자열 목록이 아니라 수학, 읽기, 발굴 보드를 구분하는 타입이 있는 데이터로 저장한다.

```dart
enum HintChannel { math, reading, discovery }

enum HintTier {
  conceptCue,
  relationshipMap,
  partialStructure,
}

class TypedHintStep {
  HintChannel channel;
  HintTier tier;
  String messageId;
  String? visualCueId;
  Set<String> relatedTokenIds;
}
```

### 6.1 수학 힌트

| 단계 | 역할 | 예시: `4×3+2` |
| --- | --- | --- |
| 1. 개념 단서 | 어떤 관계인지 떠올리게 하되 연산자를 직접 주지 않음 | “같은 수가 몇 묶음 있는지 먼저 찾아보세요.” |
| 2. 관계 연결 | 문장 속 수량, 그림과 식 블록을 연결 | “4자루씩 든 상자가 3개인 부분을 한 묶음으로 표시해 보세요.” |
| 3. 부분 구조 | 전체 정답이 아닌 첫 부분식이나 빈 슬롯 제공 | “먼저 `4 × 3`을 만들고, 낱개 수를 이어 보세요.” |

3단계 이후에도 해결하지 못하면 정답을 반복 노출하지 않는다. `guidedCompletion`으로 전환해 한 단계씩 조립하게 하고 완료 상태에는 `needsReview`를 기록한다.

### 6.2 읽기 지원

읽기 지원은 수학 힌트 사용으로 계산하지 않는다.

- 문장을 의미 단위로 나누기
- 수량·단위·비교어 강조
- 읽어주기와 용어 설명
- 시각 자료의 같은 의미를 담은 대체 설명

### 6.3 발굴 보드 힌트

발굴 힌트는 수학 힌트와 별도로 기록한다.

- 현재 만들 수 있는 유효 매치 방향 표시
- 필수 봉인과 방해 봉인 구분
- 다음 목표 봉인의 위치 범위 표시
- 마지막 단계에서만 직접 교환 경로 표시

발굴 보드 힌트 사용은 탐색 성과에는 반영할 수 있지만 수학 독립 성공을 무효화하지 않는다.

## 7. 오개념 기반 피드백

단순히 “값이 틀렸습니다”라고 표시하지 않고, 제출한 AST와 사용한 토큰을 바탕으로 가능한 오개념을 분류한다.

```dart
class MisconceptionRule {
  String id;
  String skillId;
  String feedbackId;
  HintTier nextHintTier;
  String? remediationSkillId;
}
```

우선 지원할 오개념은 다음과 같다.

| 영역 | 오개념 예시 | 피드백 방향 |
| --- | --- | --- |
| 덧셈·뺄셈 | “더 많다”, “남다”를 표면 단어만 보고 연산 선택 | 기준량, 변화량, 결과량을 그림과 연결 |
| 곱셈·나눗셈 | 묶음 수와 한 묶음의 수를 뒤섞거나 나눗셈 방향 반전 | 묶음 그림과 `전체 ÷ 묶음 수` 대응 표시 |
| 연산 순서 | 문장에 나온 순서대로만 계산 | 먼저 만들어야 하는 부분량을 묶어 표시 |
| 괄호 | 괄호를 장식 기호로 취급 | 괄호 안이 하나의 양이 되는 애니메이션 제공 |
| 단위 | 큰 단위에서 작은 단위로 갈 때 나눗셈 사용 | 단위 눈금과 1단위의 교환 비율 표시 |
| 방정식 | 빈칸 주변의 연산을 그대로 적용 | 등식 양쪽의 균형과 반대 연산 연결 |
| 둘레·넓이 | 둘레와 넓이 공식을 혼동 | 경계선과 채워진 면을 다른 시각 표현으로 대비 |
| 비율·백분율 | 전체, 한 몫, 비교량을 혼동 | 비율표 또는 100칸 모델로 기준량 표시 |
| 자료 | 평균·중앙값·최빈값을 이름으로만 기억 | 자료에서 실제로 선택·합산하는 항목 강조 |

오개념 판정은 확정적인 진단 문구로 사용자에게 표시하지 않는다. 내부적으로 “가능한 오개념”으로 기록하고, 해당 오류에 맞는 설명과 다음 힌트를 선택하는 용도로 사용한다.

## 8. 풀이 해설

정답 후 해설은 계산 과정을 다시 읽는 문장이 아니라 다음 다섯 부분으로 구성한다.

1. 문장에서 구해야 하는 양
2. 각 숫자와 단위가 뜻하는 것
3. 연산 또는 괄호를 선택한 이유
4. 부분식이 전체식으로 연결되는 과정
5. 같은 관계를 다른 상황에서 찾는 짧은 전이 질문

새 개념을 처음 배운 스테이지와 오답이 있었던 스테이지에서는 해설을 자동으로 짧게 보여 준다. 반복 연습에서는 접힌 상태로 두고 사용자가 다시 열 수 있게 한다. 해설을 읽는 행위는 별이나 보상을 깎지 않는다.

전이 질문은 새 발굴 보드를 다시 요구하지 않는 10~20초짜리 확인 문제로 제공할 수 있다. 이 결과는 완료 조건이 아니라 학습 증거로만 기록한다.

## 9. 숙련 판정

### 9.1 독립 성공

다음 조건을 모두 만족할 때 `independentSuccess` 한 건으로 기록한다.

- 이전 독립 성공과 다른 의미 `semanticFingerprint`를 사용함. stage ID·seed·표면 명사만 바꾼 반복은 불충분함
- 첫 번째 의미 있는 완성 제출이 정답임
- 수학 힌트를 사용하지 않음
- `guidedCompletion`을 사용하지 않음
- 정답식 구조가 해당 `primarySkillId`의 목표와 일치함

읽기 지원과 접근성 설정, 발굴 보드 힌트는 수학 독립 성공을 무효화하지 않는다. 보드에서 이동 수를 초과했더라도 수학 부분을 독립적으로 맞혔다면 학습 증거는 별도로 보존한다.

### 9.2 숙련 상태

| 상태 | 조건 |
| --- | --- |
| `unseen` | 아직 학습 증거가 없음 |
| `learning` | 정답 경험은 있으나 독립 성공 두 건을 충족하지 못함 |
| `provisionalMastery` | 서로 다른 변형에서 독립 성공 두 건 확보 |
| `reviewDue` | 2단계 이상 수학 힌트, 안내 조립, 오개념 또는 첫 제출 실패로 복습 필요 |
| `mastered` | 독립 성공 두 건, 전이 성공과 실제 도래한 지연 복습 성공 확보 |

한 문제의 첫 정답이나 수학 별 하나만으로 `mastered`가 되지 않는다. 독립 성공 두 건 중 최소 한 건은 `nearTransfer`, `representationTransfer` 또는 `farTransfer` 역할이어야 한다.

숙련 이력은 임의의 variant 목록이 아니라 `primarySkillId`에 귀속된 `SkillProgressSnapshot`으로 전달한다. 다른 개념의 성공 이력은 엔진이 거부하며, 안내 조립 완료는 `reviewDue`로 남고 독립 성공에는 포함되지 않는다.

## 10. 간격 복습

초기 버전의 복습 시점은 달력 날짜가 아니라 이후 완료한 스테이지 수를 기준으로 한다. 오프라인에서도 같은 결과를 내고, 실제로 다음 문제를 풀어 나가는 흐름 안에 복습을 넣기 위한 기준이다. 복습하지 않았다는 이유로 보상이나 진행을 낮추지 않는다.

### 10.1 기본 복습 일정

완료한 개념은 다음 진행 간격으로 짧게 재인출한다. 다섯 시점의 ticket을 한꺼번에 만들지 않고, 개념별 활성 ticket 하나만 유지한다. 최초 완료는 1차 ticket을 만들고, 해당 복습의 독립 성공이 확인될 때 다음 간격 ticket 하나를 이어 붙인다. 아래 간격은 직전 완료 또는 복습 성공 시점부터 센다.

- 1차: 이후 2개 스테이지 완료 시점
- 2차: 이후 6개 스테이지 완료 시점
- 3차: 이후 15개 스테이지 완료 시점
- 4차: 이후 35개 스테이지 완료 시점
- 5차: 이후 75개 스테이지 완료 시점

### 10.2 지원 필요 일정

`reviewDue` 중 지원 필요로 분류된 개념은 더 짧은 간격을 사용한다.

- 1차: 이후 1개 스테이지 완료 시점
- 2차: 이후 3개 스테이지 완료 시점
- 3차: 이후 7개 스테이지 완료 시점
- 4차: 이후 15개 스테이지 완료 시점
- 5차: 이후 35개 스테이지 완료 시점

적응형 복습은 30~90초짜리 문제 한두 개로 구성하며, 기본적으로 수학만 확인하거나 B0 수준의 익숙한 보드를 사용한다. 이 ticket은 C04~C06의 고정 나선 stage와 별도이고 주 캠페인 번호 420개에 포함하지 않는다.

각 복습은 `skillId`, 발급 variant, 정책 종류, 0부터 시작하는 `policyIndex`, 현재 간격, 도래 완료 스테이지 수와 고유 ID를 가진 ticket으로 저장한다. 지연 복습 성공은 실제 pending ticket이 도래한 뒤 해당 ID를 제출·소비했을 때만 인정한다. 다른 skill의 ticket, 아직 도래하지 않은 ticket과 이미 소비한 ID는 거부한다. 한 skill에는 활성 ticket을 하나만 두므로 저장·복원 후에도 현재 정책과 단계에서 다음 간격을 재현할 수 있다.

강화 개념(`reinforcedSkillIds`)의 ticket은 해당 개념을 실제로 평가하는 별도 의미 profile이 작성됐을 때만 발급한다. 주 개념 문제의 profile을 다른 skill의 복습 증거로 복사하지 않는다.

복습 성공은 다음 기준을 따른다.

- 도움 없이 맞히면 같은 정책의 다음 `policyIndex` ticket 하나만 만들고, 마지막 간격 성공 뒤에는 체인을 종료
- 1단계 개념 단서를 사용하면 현재 `policyIndex`와 간격을 한 번 반복
- 2~3단계 힌트 또는 안내 조립을 사용하면 기존 체인을 소비하고 지원 필요 정책의 `policyIndex = 0`으로 전환
- 같은 오개념이 반복되면 연결된 브리지 설명과 쉬운 변형을 제공

복습 완료로 만드는 후속 ticket의 도래 시점은 항상 현재 완료 스테이지 수보다 뒤에 둔다. 일반 스테이지 완료 중 지원 필요가 새로 발견되면 기존 일반 ticket보다 늦추지 않고 지원 필요 ticket 하나로 대체한다. 기존 ticket이 이미 도래했다면 현재 시점에 즉시 복습 대상으로 유지하되 과거 시점으로 되돌리지 않으며, 같은 skill에 중복 체인을 만들지 않는다.

R7은 앞 리전의 종합 전이 지역이며 유일한 복습 장소가 아니다. R1~R6 진행 중에도 위 일정에 따라 이전 개념을 짧게 재인출해야 한다.

## 11. 소프트 해금

주 학습 경로는 별, 재화, 연속 출석이나 무힌트 성공으로 잠그지 않는다.

1. 현재 스테이지를 완료하면 지역 안 다음 스테이지를 연다. C06 S10은 지역 숙련 종료라 다음 링크가 없다.
2. 도움을 받아 완료해도 진행은 허용하고 `reviewDue`와 복습 일정을 기록한다.
3. 다음 새 개념이 취약한 선수개념에 직접 의존하면 시작 전에 20초 확인 문제를 제공한다.
4. 확인 문제에 실패하면 60~90초 브리지 설명과 안내 연습을 제공한 뒤 계속 진행한다.
5. 챕터 관문을 도움으로 완료하면 다음 챕터를 열되, 첫 3개 스테이지 안에 해당 개념 복습을 삽입한다.
6. C03 S10 접근 관문을 완료하면 현재 리전 C04와 다음 리전을 함께 연다. 도움으로 완료해도 두 경로를 모두 열고 지역 지도에 복습 필요 표시를 남긴다.
7. 이미 숙련한 사용자는 선수개념 확인을 통과해 소개·안내 연습을 빠르게 넘길 수 있다.

브리지 설명과 복습 카드는 실패 벌칙이 아니다. 생명, 대기 시간, 광고 시청이나 재화 소비를 요구하지 않는다.

## 12. 우선 재구성할 챕터

코어 210개 중 다음 네 챕터는 한 번씩 소개되는 개념이 많거나 관문이 해당 챕터를 평가하지 않아 실제 문제 제작 전에 재구성해야 한다.

### 12.1 R2 C3 규칙의 고목

현재 입출력표, 역규칙, 이차 차이, 사각수, 삼각수와 복합 규칙이 한 챕터에 함께 있다. 10개 주 경로는 `입출력표의 정방향 규칙 → 다른 입력에 전이 → 역규칙 → 정·역 혼합 확인`에 집중한다.

- 이차 차이, 사각수, 삼각수는 후속 선택 챕터 또는 별도 도전 묶음으로 이동
- 표의 입력·규칙·출력을 시각적으로 분리
- 같은 `primarySkillId`를 여러 입력과 역문제로 재사용
- 최종 관문은 정방향과 역방향을 모두 확인

### 12.2 R4 C1 반대 연산의 오솔길

덧셈·뺄셈 역연산을 배우는 중간에 합과 차, 연속수와 곱셈형 방정식이 섞여 있다. C1은 덧셈·뺄셈 빈칸과 등식 균형에 집중한다.

- 곱셈형 방정식은 R4 C2로 이동
- 합과 차, 연속수는 R4 C3의 관계식 묶음으로 이동
- 수직선과 저울 표현을 사용해 반대 연산의 이유를 설명
- 최종 관문은 시작값·변화량·결과값 위치가 다른 덧셈·뺄셈 식을 구별

### 12.3 R5 C3 각과 공간의 전망대

각, 대칭, 좌표, 부피, 모서리를 한 문제씩 다루고 최종 관문은 이전 챕터의 복합 넓이를 평가한다. 주 경로는 서로 연결할 수 있는 `각의 관계와 격자 위치`에 집중한다.

- 직각, 일직선, 삼각형·사각형의 각을 소개·연습·전이 구조로 확대
- 좌표와 격자 거리는 별도의 작은 묶음으로 구성
- 부피와 입체도형 모서리는 후속 선택 챕터로 이동
- 최종 관문은 각 또는 격자 개념을 직접 평가하고 이전 넓이 문제를 사용하지 않음

### 12.4 R6 C3 자료의 등대

그림표, 막대그래프, 합, 평균, 범위, 최빈값, 중앙값과 비율 예측을 한 번씩 다루고 있다. 주 경로는 `자료 읽기·비교 → 합과 차 → 평균과 범위 → 혼합 확인`으로 좁힌다.

- 그림표·막대·표에서 같은 자료를 다른 표현으로 읽는 전이 제공
- 평균은 구체적인 고르게 나누기 표현에서 식으로 이동
- 중앙값·최빈값은 충분한 슬롯을 확보한 후속 묶음으로 이동
- 비율 예측은 R6 C1 복습 또는 R7 종합으로 이동
- 최종 관문은 자료 표현 선택, 합·차, 평균·범위를 확인

나머지 코어 챕터도 10스테이지 역할과 숙련 조건을 기준으로 재검토하되, 위 네 챕터를 P0로 우선 수정한다. 코드 카탈로그에서는 위 40개의 variant·전이 역할을 다른 경로의 준비 증거로 사용하지 않는다. 코어에서는 총 86개를 `requiresRevision`, 124개를 구조 후보 `planned`로 유지한다. 실제 의미 변형이 미작성인 C04~C06 210개도 모두 `requiresRevision`이므로 전체 학습 상태는 296개 `requiresRevision`, 124개 `planned`다. `requiresRevision` 상태의 stage는 실제 문제 제작과 플레이 가능 승격 대상에서 제외한다.

## 13. FHD 스마트폰 3열 학습 슬롯

학습 UI는 질문·발굴 보드·정답 공간이 동시에 보이는 3열 레이아웃의 높이를 늘리지 않아야 한다. 기준 구조는 다음과 같다.

| 왼쪽 열 | 가운데 열 | 오른쪽 열 |
| --- | --- | --- |
| 질문, 상황 아이콘, 접을 수 있는 개념 목표 | 5×5 또는 6×6 발굴 보드 | 획득 블록, 정답식, 확인·도움 버튼 |

### 13.1 지속 표시

- 개념 목표는 한 줄 chip 또는 최대 두 줄로 제한
- 질문 카드와 상황 그림은 기존 왼쪽 영역 안에서 교체 표시
- 오른쪽에는 `도움` 버튼 하나만 지속 표시
- 힌트 단계 수와 사용 상태는 작은 텍스트·Semantics로 제공
- 보드와 정답식의 터치 영역은 학습 UI 때문에 줄이지 않음

### 13.2 필요할 때만 표시

- 개념 소개는 스테이지 시작 전 짧은 전체 화면 카드나 현재 열을 대체하는 패널로 제공
- 힌트는 오른쪽 열의 보조 패널 또는 화면 내 overlay로 열고 기존 요소 위에 계속 쌓지 않음
- 오개념 피드백은 질문 카드의 보조 영역을 일시적으로 대체
- 정답 후 해설은 전체 높이를 늘리는 새 영역이 아니라 접을 수 있는 overlay나 완료 카드로 표시
- 패널이 열린 동안 보드 이동 수와 시간이 진행되지 않음

`800×360`, `720×320`, SafeArea 적용 후 `680×300`에서 질문, 보드, 정답식과 기본 액션이 동시에 남아 있어야 한다. text scale 130%에서는 개념 목표와 해설을 축약하지 않고 스크롤 가능한 overlay로 전환한다.

스크린리더에서는 질문, 시각 자료 설명, 보드, 획득 블록, 정답식, 도움 순서로 포커스를 이동한다. 시각 자료가 필요한 단위·도형·표 문제는 같은 의미의 텍스트 설명을 반드시 제공한다.

### 14.1 핵심 지표

| 지표 | 의미 |
| --- | --- |
| 선수개념 대비 관문 향상 | 같은 개념의 진입 확인과 챕터 관문 사이 독립 정답률 변화 |
| 독립 성공률 | 수학 힌트 없이 서로 다른 변형을 해결한 비율 |
| 가까운 전이 성공률 | 숫자·문장 표현이 달라져도 같은 관계를 적용한 비율 |
| 먼 전이 성공률 | 그림·표·새 상황에서 관계를 식으로 옮긴 비율 |
| S+2·S+6·S+15·S+35·S+75 유지율 | 기본 복습 일정에서 도움 없이 다시 성공한 비율 |
| S+1·S+3·S+7·S+15·S+35 회복률 | 지원 필요 일정에서 독립 성공으로 전환된 비율 |
| 힌트 의존 감소 | 같은 개념의 반복에서 최고 수학 힌트 단계가 낮아지는지 |
| 오개념 재발률 | 같은 오개념 후보가 다른 변형에서도 반복되는 비율 |
| 독립 성공까지의 기회 수 | 소개 후 두 번째 독립 성공까지 필요한 문제 수 |
| 학습 경로 지속률 | 브리지·복습 제공 후 다음 스테이지로 이어지는 비율 |

### 14.2 반드시 분리할 지표

- 수학 오답과 보드 실패
- 수학 힌트와 발굴 경로 힌트
- 읽기 지원과 개념 지원
- 독립 완료와 안내 조립 완료
- 일반 문제와 지연 복습 문제
- 기본 UI와 접근성 프로필

완료 시간과 이동 수는 게임 밸런스 지표이며 학습 효과의 직접 지표로 사용하지 않는다. 빠르게 맞힌 것보다 다른 문맥과 지연 시점에서 올바른 관계를 선택했는지가 우선이다.

### 14.3 검증 단계

1. 수학·교육 관점의 콘텐츠 검수로 선수개념과 오개념 규칙 확인
2. seed별 정답 AST, 표현 동등성, 힌트 순서 정적 검증
3. 대표 사용자 관찰로 설명 이해와 화면 부담 확인
4. 챕터 진입 확인, 관문과 지연 복습 데이터 수집
5. 특정 연령·학년이나 학습 효과를 홍보하기 전에 별도 평가 설계와 결과 검토

초기 출시에서는 “개념별 연습과 복습을 제공한다”는 기능 설명은 가능하지만, 측정 결과 없이 성취 향상이나 장기 학습 효과를 보장하는 표현은 사용하지 않는다.

## 15. 구현 우선순위

### P0: R1 실제 제작 전

- 재사용 가능한 `primarySkillId`와 `StageLearningRole` 정의
- 선수개념·복습 개념·변형 ID를 포함한 stage 학습 metadata 추가
- 타입이 있는 3단계 힌트, 오개념 규칙, 풀이 해설 schema 정의
- 완료와 별에서 분리된 학습 증거·숙련 상태 모델 추가
- R2 C3, R4 C1, R5 C3, R6 C3 재구성
- 학습 역할과 관문 범위를 검사하는 validator 추가

### P1: R1 코어 30개와 첫 나선 변형 활성화

- R1 각 개념의 소개·안내·독립·전이·관문 문제 작성
- 브리지 설명과 `reviewDue` 처리
- 완료 스테이지 기준 기본 +2/+6/+15/+35/+75, 지원 필요 +1/+3/+7/+15/+35 복습 큐
- C04에서 실제 수·문맥·표현이 달라지는 source-linked 변형을 작성하고 의미 fingerprint 검증
- 수학·읽기·발굴 힌트 사용 기록 분리
- FHD 3열 overlay와 접근성 설명 검증

### P2: 후속 리전 확장

- 수열, 단위, 도형, 비율표와 자료 renderer 연결
- 오개념 판정 범위 확대
- 숙련 상태에 따른 소개 건너뛰기와 복습 선택
- 독립 성공, 전이와 지연 유지 지표 분석
- 대표 사용자 결과를 반영한 문제 순서와 도움 단계 조정

이 순서를 완료한 스테이지만 `planned → puzzleReady → playable`로 승격한다. 플레이 가능 여부와 학습 설계 완료 여부를 같은 상태로 간주하지 않는다.
