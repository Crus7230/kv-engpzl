# 스테이지·난이도 설계

> 이 문서는 리전 구조를 복구하기 전에 만든 30스테이지 파일럿 기록이다. 현재 캠페인의 권위 있는 구성은 [REGIONAL_STAGE_CURRICULUM.md](REGIONAL_STAGE_CURRICULUM.md)의 `7리전 × 6챕터 × 10스테이지 = 420스테이지`이며, 아래 표는 난도 축과 초기 수치의 설계 근거로만 유지한다.

## 1. 목적과 범위

이 문서는 문장을 수식으로 바꾸는 문제와 매치-3 발굴을 결합한 캠페인의 스테이지 구조, 난도 곡선, 보상과 실패 보정을 정의한다.

기존 앱의 `7영토·750스테이지`처럼 같은 템플릿을 긴 번호 체계에 반복 배치하지 않는다. 이 파일럿은 직접 검토할 수 있는 `3챕터 × 10스테이지 = 30스테이지`로 시작했으며, 여기서 확정한 한 스테이지의 단위를 현재 420스테이지 지역 카탈로그에도 적용한다.

- 문장제 1개
- 발굴 보드 1개
- 정답 수식 1개 또는 명시적으로 허용한 동치식 집합
- 목표 플레이 시간 2~4분
- 재현 가능한 문제 seed와 보드 seed

다음 스테이지는 현재 스테이지 완료만으로 연다. 별 개수, 재화, 연속 출석으로 주 학습 경로를 잠그지 않는다.

이 문서의 30개 수식과 이동 수는 콘텐츠 제작과 자동 풀이 검증을 시작하기 위한 1차 목표값이다. 실제 seed별 기준 경로와 사람 플레이 결과가 나오기 전까지 확정 밸런스로 취급하지 않는다.

## 2. 반복을 피하는 캠페인 구조

### 2.1 파일럿 챕터

| 챕터 | 스테이지 | 학습 중심 | 매치 중심 | 마지막 확인 |
| --- | --- | --- | --- | --- |
| 1. 모으기와 남기기 | 01~10 | 덧셈, 뺄셈, 합과 차를 나타내는 문장 | 안내 교환에서 자유 매치와 경로 선택까지 | 10 |
| 2. 묶기와 나누기 | 11~20 | 곱셈, 나눗셈, 두 단계 식 | 다수 봉인과 2층 봉인 입문 | 20 |
| 3. 순서의 유적 | 21~30 | 연산 순서, 괄호, 중복 숫자, 단위와 관계식 | 장애물과 특수 타일 입문 | 30 |

각 챕터는 개념 안내, 낮은 매치 난도의 개념 연습, 숫자·상황 전이, 매치 규칙 도입, 혼합 적용, 확인 문제의 순서를 가진다. 새 수학 개념과 새 매치 규칙을 같은 스테이지에서 동시에 크게 올리지 않는다.

### 2.2 후속 콘텐츠 원칙

- 새 챕터는 새로운 수학 관계나 새로운 핵심 조작이 있을 때만 10개 단위로 추가한다.
- 숫자, 배경, 문장 명사, seed만 바꾼 문제는 새 캠페인 번호로 만들지 않는다.
- 같은 스테이지의 재플레이는 검증된 숫자·상황·보드 seed 변형으로 제공한다.
- 개인별 취약 개념 복습과 주간 도전은 캠페인 스테이지 번호와 분리한다.
- 파일럿 30개 데이터가 검증되기 전에는 60개 이상의 주 경로를 미리 만들지 않는다는 당시 원칙이었다. 현재는 코어 210개와 source-linked 나선 경로 210개, 총 420개 제작 슬롯으로 확장했지만 검증 전 슬롯을 `playable`로 승격하지 않는 원칙은 유지한다.

## 3. 난이도 모델

하나의 종합 난도 숫자만 저장하지 않는다. 수학, 매치, 수식 구성, 읽기 부담을 독립 축으로 관리한다.

### 3.1 수학 난도 `M`

| 단계 | 의미 |
| --- | --- |
| M0 | 연산 의미를 화면 안내와 함께 확인 |
| M1 | 두 수와 연산자 하나로 된 식 |
| M2 | 세 수와 연산자 두 개로 된 식 |
| M3 | 연산 우선순위, 괄호, 같은 값의 독립 토큰 |
| M4 | 단위 변환, 합과 차 등 관계를 다른 식으로 변환 |

숫자가 커졌다는 이유만으로 M단계를 올리지 않는다. 필요한 관계 추론과 수식 구조가 달라질 때만 올린다.

### 3.2 매치 난도 `B`

| 단계 | 문양·봉인·규칙 |
| --- | --- |
| B0 | 문양 4종, 1층 필수 봉인 2~3개, 안내 경로, 방해 봉인 없음 |
| B1 | 문양 5종, 1층 필수 봉인 2~4개, 자유 매치, 방해 봉인 없음 |
| B2 | 문양 5종, 필수 봉인 최대 5개, 경로 선택, 방해 봉인 최대 1개 |
| B3 | 2층 봉인 1개 또는 먼지 장애물 최대 3칸 중 한 종류만 사용 |
| B4 | 4개 매치로 만드는 특수 타일 1종 요구, 다른 새 장애물과 중첩하지 않음 |

보드 행·열 수는 B단계에 포함하지 않는다. 5×5와 6×6은 기기 대응을 위한 동등 난도 표현이다.

### 3.3 수식 구성 난도 `C`

| 단계 | 의미 |
| --- | --- |
| C0 | 안내 슬롯을 사용하는 3블록 식 |
| C1 | 자유롭게 구성하는 3블록 식 |
| C2 | 연산자 두 개 또는 중복 토큰을 포함하는 최대 5블록 식 |
| C3 | 괄호를 포함하는 최대 7블록 식 |

파일럿과 현재 지역 카탈로그에서는 정답식을 최대 7블록으로 제한한다. 이는 저높이 화면에서 발굴 보관함과 정답식을 동시에 보여주기 위한 콘텐츠 제약이기도 하다.

### 3.4 읽기 난도 `R`

| 단계 | 의미 |
| --- | --- |
| R0 | 그림과 한 문장 중심, 한 가지 관계 |
| R1 | 두 조건 또는 세 수량을 포함하는 문장 |
| R2 | 단위나 합·차 관계를 해석해야 하는 문장 |

읽기 난도는 수학 난도와 별도로 저장한다. 읽어주기, 핵심어 강조, 그림 설명을 사용해도 수학 난도나 보상이 낮아지지 않는다.

### 3.5 난도 상승 규칙

- 한 스테이지에서 M과 B를 동시에 올리지 않는다.
- M이 오르면 B를 유지하거나 한 단계 낮춘다.
- B3 또는 B4를 처음 소개할 때는 M1 수준의 익숙한 식을 사용한다.
- 한 스테이지에 새 매치 규칙은 하나만 넣는다.
- 파일럿과 현재 지역 카탈로그에서는 문양 최대 5종, 봉인 최대 5개, 장애물 최대 3칸으로 제한한다.
- 시간 제한은 난도 축으로 사용하지 않는다. 시간은 조정 지표일 뿐 실패 조건이나 별 조건이 아니다.

## 4. 5×5·6×6 동등 변형

보드 크기는 화면 크기에 따라 선택하지만 같은 스테이지의 난도를 바꾸지 않는다.

| 화면 조건 | 보드 표현 |
| --- | --- |
| 너비 720dp 미만 또는 높이 400dp 미만 | 5×5 compact fixture |
| 너비 720dp 이상이고 높이 400dp 이상 | 6×6 expanded fixture 사용 가능 |

`800×360`, `720×320`, SafeArea 적용 후 `680×300`은 모두 5×5를 사용한다.

같은 `stageId`의 두 fixture는 다음 조건을 만족해야 한다.

- `requiredTokenPlan`이 같다.
- 문양 종류 수가 같다.
- 필수·방해 봉인의 수와 단계가 같다.
- 장애물 종류와 총 타격 요구량이 같다.
- 특수 타일 요구 여부가 같다.
- 검증된 기준 경로 이동 수 `W`가 같다.
- 탐색 별 기준 `P`와 실패 이동 한도 `L`이 같다.
- 필수 조각이 발굴되는 순서는 달라도 수학적 정보량과 완료 가능성은 같다.

각 크기는 독립 `boardFixtureId`와 `boardSeedSet`을 가진다. 단순히 5×5 seed를 6×6으로 늘리거나 자르지 않는다. 두 표현의 기준 경로를 같게 만들 수 없다면 해당 seed 쌍은 활성 카탈로그에 넣지 않는다.

compact 화면에서는 시각 타일 크기가 44dp보다 조금 작아져도 실제 제스처 영역은 최소 44dp를 유지한다. 색상뿐 아니라 문양과 봉인 윤곽으로 상태를 구분한다.

## 5. 이동 수 표기

아래 스테이지 표의 `W/P/L`은 다음을 뜻한다.

- `W`: 자동 검증으로 재생할 기준 완료 경로의 목표 이동 수
- `P`: 탐색 별을 얻는 기준 이동 수
- `L`: 기본 프로필에서 이동 수 소진으로 판정하는 한도

현재 파일럿 표와 420개 지역 카탈로그의 `W/P/L`은 제작 목표값이며 아직 solver 실측값이 아니다. fixture 승격 이후의 `W`만 구현된 solver가 실제로 재생할 수 있는 기준 경로를 뜻한다. `W`는 이론상 최솟값이 아니며, 자동 연쇄가 크게 발생해도 필수 조각이 유실되지 않아야 한다.

## 7. 별 평가와 해금

별은 최대 3개이며 서로 다른 숙련을 나타낸다.

| 별 | 획득 조건 |
| --- | --- |
| 완료 별 | 스테이지를 올바르게 끝냄. 지원 fixture나 단계별 조립 완료도 포함 |
| 수학 별 | 첫 번째 의미상 완성된 제출이 정답이고 2단계 이상의 수학 힌트를 사용하지 않음 |
| 탐색 별 | 현재 기기 fixture의 `P` 이내에 발굴하고 직접 경로 힌트를 사용하지 않음 |

문법상 제출할 수 없는 조작, 단순 드래그 실수, 무효 교환은 수학 별에 영향을 주지 않는다. 자동 섞기는 이동 수에 포함하지 않는다.

큰 글자, 읽어주기, 색각 보정, 모션 감소와 같은 접근성 설정은 별에 영향을 주지 않는다. 별 최고 기록은 재도전으로 갱신할 수 있다.

다음 스테이지와 다음 챕터는 완료 별만으로 연다. 별은 유적 복원, 수식 도감과 같은 누적 보상에 사용하고 소비 재화와 분리한다. 3별 완료 후에는 별과 별개인 선택형 도전 메달 재플레이를 열 수 있다.

## 8. 실패와 보정

생명, 대기 시간, 광고 부활은 사용하지 않는다. 수식 오답은 보드 이동 수를 차감하지 않고 현재 식과 발굴 조각을 보존한다.

### 8.1 이동 수 소진

1. 마지막 필수 조각까지 검증 경로가 1~2회 남았으면 한 번만 `집중 기회 +2회`를 제공한다.
2. 첫 실패는 같은 문제와 다른 검증 seed로 무료 재도전한다.
3. 두 번째 실패부터 지원 fixture를 제안한다.
   - 이동 한도 약 25% 증가
   - 방해 봉인 제거
   - 2층 봉인은 1층으로 변경
   - 특수 타일 요구는 선택 목표로 변경
4. 세 번째 실패에는 처음 두 교환을 안내하고 수식의 첫 구조 슬롯을 표시한다.
5. 단계별 도움으로 완료해도 다음 스테이지를 열고 내부 진행 데이터에만 `reviewDue`를 기록한다.

재도전 시 문제 문장, 확인한 봉인 유형, 수학 힌트 단계는 유지한다. 보드와 실제 토큰 instance는 새 fixture에 맞춰 다시 만든다.

### 8.2 수식 오답

| 횟수 | 피드백 |
| --- | --- |
| 첫 오답 | 현재 식을 유지하고 연산 관계나 계산 오류 원인만 설명 |
| 두 번째 | 문장 속 수량과 대응하는 수식 블록을 연결 |
| 세 번째 | 부분 식 또는 연산 순서 틀을 제공 |
| 이후 | 단계별 조립을 수행하게 하고 같은 개념의 쉬운 복습을 선택 카드로 제안 |

## 9. 사용자 진행 프로필

나이와 학년을 요구하기보다 도움 수준을 선택하게 한다.

| 프로필 | 규칙 | 보상 |
| --- | --- | --- |
| 기본 | 표의 `L`, 기본 봉인 라벨과 힌트 간격 사용 | 기본 `P`로 탐색 별 평가 |
| 편안하게 | 이동 한도 약 25% 증가, 봉인 라벨 유지, 유효 매치 표시를 더 빨리 제공 | 접근성 불이익 없이 3별 가능. 별도 보정 `P` 사용 |
| 도전 | 해당 스테이지 완료 후 재플레이에서만 제공, 이동 한도를 `P` 근처로 축소하고 자동 경로 표시를 끔 | 주 경로·별과 분리된 도전 메달 제공 |

프로필 선택은 수학 문제의 관계나 정답 AST를 바꾸지 않는다. 숙련 비교가 필요하면 별이 아니라 `completionMode`, 실제 이동 수, 힌트 단계 등의 내부 기록을 사용한다.

## 10. 스테이지 데이터 필드 초안

스테이지 manifest에는 다음 값이 필요하다.

- `stageId`, `chapterId`, `order`
- `templateId`, `learningObjective`, `expressionShape`
- `mathTier`, `boardTier`, `compositionTier`, `readingTier`
- `requiredTokenPlan`, `decoyTokenPlan`
- `gemKinds`, `sealLayers`, `obstaclePlan`, `specialRule`
- `compact5FixtureId`, `expanded6FixtureId`
- `referenceMoves`, `parMoves`, `moveLimit`
- `supportFixtureId`, `targetDurationSeconds`
- `problemSeedSet`, `boardSeedSet`, `contentVersion`

각 스테이지에는 최소 3개의 검증 seed 쌍을 준비한다. 모든 seed는 초기 매치 없음, 최소 한 개의 유효 교환, 필수 조각 유실 없음, `L` 이내 완료 경로 존재 조건을 통과해야 한다.

## 11. 현재 구현 지원 상태

다음 표는 이 문서의 목표가 아니라 현재 소스에서 확인한 상태를 나타낸다.

| 항목 | 상태 | 현재 범위와 부족한 부분 |
| --- | --- | --- |
| 인접 교환과 3개 이상 직선 매치 | 구현됨 | 무효 위치, 비인접, 무매치 상태를 구분하며 무매치는 이동 수를 차감하지 않음 |
| 낙하·보충·연쇄 | 구현됨 | 고정 refill source를 사용하는 순수 Dart 엔진이 연쇄를 처리함 |
| 1층 매치 셀 봉인 | 구현됨 | 매치로 제거된 셀의 `buriedTarget`을 즉시 발굴함. 주변 매치로 봉인을 타격하는 일반 규칙은 아직 없음 |
| 필수·비필수 발굴 토큰 | 부분 구현 | stage 카탈로그가 시작·필수 봉인·방해 토큰을 구분하고 정적 검증하지만, 방해 토큰을 포함한 일반 보드 생성과 플레이 UX는 없음 |
| B0 안내 경로 | 계획 | 안내 교환 인프라는 B1 별도 프로토타입에서만 3회 경로로 검증됨. 지역 카탈로그용 B0 manifest와 범용 안내 경로 모델은 없음 |
| B1 자유 매치 | 부분 구현 | 핵심 교환·발굴은 가능하나 seed 생성기, 자동 섞기 실행, 기준 경로 계산과 일반 fixture 카탈로그가 없음 |
| B2 경로 선택·방해 봉인 | 부분 구현 | 여러 buried target과 required subset 표현은 가능함. 방해 토큰 UX, 봉인 라벨 규칙, 난도 검증은 없음 |
| B3 2층 봉인 | 계획 | 봉인 내구도·타격 단계 데이터와 엔진 처리가 없음 |
| B3 먼지 장애물 | 계획 | 장애물 셀 모델, 제거 규칙, 이동 가능성 검사가 없음 |
| B4 특수 타일 | 계획 | 4개 매치 생성물, 발동, 결합 규칙 모델이 없음 |
| 5×5·6×6 동등 fixture | 부분 구현 | 프로토타입은 독립 fixture ID와 seed로 같은 3회 경로·W/P/L을 검증함. 현재 크기별 seed는 1개뿐이며 420개 일반 stage의 최소 3개 seed 쌍은 아직 모델링·검증되지 않음 |
| 이동 수 제한 | 구현됨 | accepted swap에만 1회 차감하고 0에서 추가 교환을 막음 |
| dead-board 처리 | 부분 구현 | 유효 교환 존재 여부는 감지하지만 무료 자동 섞기와 검증된 fallback 전환은 없음 |
| 수식 AST와 정답 검증 | 부분 구현 | 사칙연산, 괄호, 독립 토큰, 정확한 유리수와 7리전·420 stage의 M/B/C/R 메타데이터를 구현함. 420개 실제 Puzzle/token manifest와 일반 생성기는 미작성 |
| 별 3종 평가 | 부분 구현 | `StageAttemptMetrics`로 완료·수학·탐색 별을 각각 평가하고 순수 Dart로 검증함. 영구 저장과 진행 화면 통합은 없음 |
| 실패 보정과 지원 fixture | 계획 | 집중 기회, 재시도 seed, 지원 프로필, `reviewDue` 상태가 없음 |
| 사용자 진행 프로필 | 계획 | 기본·편안하게·도전 규칙과 프로필별 이동·힌트 정책이 없음 |
| 7리전·420스테이지 카탈로그 | 설계 구현 | 7리전×6챕터×10의 모든 콘텐츠 슬롯이 `planned`이며 출시 카탈로그의 `playable`은 0개임. C04~C06은 실제 의미 변형 미작성으로 학습 상태 `requiresRevision`이며 별도 프로토타입 1개만 끝까지 실행 검증됨 |

따라서 현재 엔진으로 바로 제작할 수 있는 범위는 B0~B2의 일부이다. 우선 계산의 평원 30개에 실제 문제와 검증 fixture를 제작해 순차적으로 `playable`로 승격해야 한다. B3의 다층 봉인·장애물과 B4의 특수 타일을 사용하는 후속 리전 스테이지는 엔진 확장 전에는 활성 상태로 배포할 수 없다.

## 12. 조정과 완료 기준

초기 목표 지표는 다음과 같다.

- 완료 시간 중앙값 2~3분
- 완료 시간 90백분위 4분 이하
- 첫 시도 완료율: 챕터 1 약 85%, 챕터 2 약 80%, 챕터 3 약 75%
- seed 때문에 완료할 수 없는 판 0건
- 보드 운이 주원인인 실패율 5% 미만

보드 실패율이 높으면 먼저 `L`, 봉인 단계, 방해 봉인 수, 문양 수 순서로 조정한다. 수학 오답률이 높으면 문제 문장, 그림 대응, 단계형 힌트를 조정한다. 한 번의 밸런스 수정에서 M과 B를 동시에 낮추지 않아 실패 원인을 추적할 수 있게 한다.

각 리전의 코어 30개와 연결된 나선 문제를 활성화하기 전에 다음 검증이 필요하다.

1. stage별 5×5·6×6 fixture 쌍의 동일 `W/P/L` 검증
2. problem seed와 board seed 조합 자동 재생
3. 수식 AST와 필수 token multiset 정적 검증
4. 800×360, 720×320, 680×300에서 7블록 식까지 한 화면 표시 확인
5. 접근성 프로필이 정답, 이동 수 저장, 별 평가를 훼손하지 않는지 확인
6. 대표 사용자 플레이로 2~4분 목표와 실패 보정 시점을 조정
