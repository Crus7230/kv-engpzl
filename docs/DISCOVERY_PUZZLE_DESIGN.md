# 수식 조각 발굴 퍼즐 게임 디자인

## 1. 문서 목적

이 문서는 기존의 “문장을 식으로 바꾸는 퍼즐”을 다음 두 활동이 연결된 게임으로 확장하는 설계 기준을 정의한다.

1. 매치 퍼즐을 풀어 문제 해결에 필요한 숫자·연산자·괄호 조각을 발굴한다.
2. 발굴한 조각을 문장에 맞게 배열해 올바른 수식을 완성한다.

핵심은 매치 퍼즐과 수학 문제가 따로 노는 것을 피하고, 플레이어가 문장의 수학적 관계를 생각하며 어떤 조각을 먼저 발굴할지 선택하게 만드는 것이다. 특정 상용 게임의 상표, 캐릭터, 아트, 음향, 맵, 고유 레벨 구성은 사용하지 않는다. 인접 교환, 3개 이상 연결, 연쇄, 특수 타일처럼 장르에 널리 쓰이는 일반 원칙만 사용하고, “수학 유적에서 수식 조각을 복원한다”는 독자적인 시각 언어와 규칙으로 구성한다.

## 2. 플레이어 경험 목표

한 판의 플레이 감정 곡선은 다음과 같다.

- 이해: 문장을 읽고 필요한 계산 관계를 추측한다.
- 탐색: 보드에서 어느 봉인 조각을 먼저 열지 선택한다.
- 성취: 연쇄 반응으로 숫자나 기호가 발굴된다.
- 구성: 발굴한 조각을 즉시 수식 보드에 놓아 가설을 만든다.
- 검증: 식의 문법, 관계, 계산 결과를 확인한다.
- 설명: 정답이 문장과 어떻게 연결되는지 짧게 복습한다.

권장 한 판 길이는 초반 45~75초, 일반 90~150초, 도전 스테이지 최대 3분이다. 매치 보드가 길어져 수학 문제를 잊게 만들지 않도록 3분을 일반 상한으로 둔다.

## 3. FHD 스마트폰 가로 화면 규격

### 3.1 해상도 기준

1920×1080은 16:9 패널의 물리 픽셀 수이며 Flutter 레이아웃은 기기 배율이 적용된 논리 픽셀을 사용한다. 실제 최신 스마트폰은 2340×1080 또는 2400×1080의 19.5:9·20:9 FHD+가 많고, DPR 3.0이면 각각 약 780×360·800×360 논리 화면이 된다. 디스플레이 배율과 시스템 내비게이션, 카메라 홀·노치를 적용하면 720×320 또는 SafeArea 후 680×300 수준까지 낮아질 수 있다. 따라서 16:9 높이를 기본으로 가정하지 않고 초광폭 논리 viewport와 실제 SafeArea 제약을 기준으로 설계한다.

필수 검증 뷰포트:

| 등급 | 논리 화면 | 용도 |
| --- | --- | --- |
| ultra-safe | 680×300 | SafeArea 적용 후 저높이 최소 실사용 조건 |
| ultra-compact | 720×320 | 배율이 큰 20:9 스마트폰 |
| ultra-standard | 800×360 | 2400×1080, DPR 3.0의 주 설계 기준 |
| legacy-compact | 640×360 | 1920×1080, DPR 3.0의 16:9 회귀 조건 |
| large-wide | 960×432 | 저배율 20:9 또는 태블릿 가로 검증 조건 |

가로 모드에서 `SafeArea`를 적용한 뒤 `LayoutBuilder`의 실제 제약으로 배치한다. 사용자가 시스템 글자 크기를 130%로 설정해도 핵심 질문, 남은 이동 수, 보드, 발굴 조각, 수식 공간, 확인 버튼은 화면에서 사라지지 않아야 한다.

### 3.2 한 화면 동시 노출 원칙

플레이 중 다음 여섯 항목은 다른 화면이나 스크롤로 이동하지 않고 항상 보여야 한다.

1. 축약되지 않은 핵심 질문
2. 문제 상황을 나타내는 아이콘 또는 간단한 도식
3. 남은 이동 수와 발굴 진행도
4. 매치 보드
5. 발굴한 숫자·기호 보관함과 수식 정답 공간
6. 힌트·되돌리기·확인 행동

긴 해설, 별 세부 점수, 다음 문제 예고는 플레이 중 상시 노출 대상이 아니다. 정답 후 결과 패널이나 상세 팝업으로 분리한다.

### 3.3 compact 화면 배치

모든 가로 화면의 기본 구조는 상단 HUD와 `질문·아이콘 / 매치 보드 / 수식·정답`의 3열 본문이다. 800×360·720×320·680×300의 초광폭 저높이 화면에서는 같은 구조를 유지하되 compact-height 규격을 적용한다.

| 영역 | 권장 크기 | 내용 |
| --- | --- | --- |
| 상단 HUD | 높이 40~44dp | 뒤로가기, 스테이지, 이동 수, 발굴 수, 설정 |
| 문제 패널 | 너비 128~156dp | 핵심 질문, 상황 도식 44~48dp |
| 매치 패널 | 너비 최대 246dp | 5×5, 실제 grid 약 226~240dp |
| 수식 패널 | 나머지 265~328dp | 44dp 수식 행, 피드백, 행동 버튼 |
| 영역 간격 | 4~6dp | 각 패널의 시각적 분리 |

상단 HUD를 제외한 본문 높이에서 보드가 기준 크기를 결정한다. 좌우 패널은 보드 높이를 넘지 않으며 내부 세로 스크롤을 기본 동작으로 사용하지 않는다.

`SafeArea` 적용 후 너비가 720dp 미만이거나 높이가 400dp 미만이면 5×5 compact 규격을 사용한다. 높이가 390dp 미만이면 compact-height 모드로 전환해 다음 순서로 시각 요소를 축소한다.

1. 장식 배경과 캐릭터 연출을 숨긴다.
2. 상황 도식을 44dp로 줄이되 숨기지 않는다.
3. HUD를 44dp, 패널 내부 여백을 3~5dp로 줄인다.
4. 기본 6×6 보드를 5×5 compact-safe 폴백으로 전환한다.
5. 질문 패널의 중복 발굴 진행표를 숨기고 HUD 진행표를 유지한다.
6. 수식 보관함과 답안 행을 각각 44dp로 줄인다.

질문 본문과 정답 조각 글자는 마지막까지 축소하지 않는다. 질문은 14sp 이상, 숫자·연산자 조각은 18sp 이상, 주요 버튼은 높이 44dp 이상을 유지한다. 타일 사이가 좁더라도 각 타일의 제스처 영역은 가능한 44×44dp를 확보하고, 최소 안전 영역에서만 40×40dp까지 허용한다.

### 3.4 standard·large 화면 배치

- `SafeArea` 적용 후 너비가 720dp 이상이고 높이가 400dp 이상일 때만 6×6을 표시한다.
- 기본 3열 너비 비율은 문제·아이콘 24~26%, 매치 보드 40~44%, 수식·정답 30~34%다.
- 6×6 보드는 264~300dp 정사각형으로 배치하고, 각 타일의 제스처 영역은 44dp 이상을 목표로 한다.
- 너비가 720dp 미만이거나 높이가 400dp 미만이면 5×5 compact 보드로 전환한다. 같은 stageId라도 compact 전용으로 검증된 boardSeed와 봉인 배치를 사용한다.
- 840dp 이상에서는 문제 패널과 수식 패널의 너비를 늘리고 보드는 정사각형을 유지한다.
- 960×432 이상에서는 질문 아이콘과 간단한 관계 도식을 함께 보여줄 수 있다.
- 남는 공간을 타일 수 증가로만 소비하지 않는다. 질문 가독성, 수식 조작 영역, 피드백 공간을 먼저 확장한다.
- 어떤 너비에서도 핵심 패널의 위치 순서는 `질문 → 매치 보드 → 수식`으로 유지한다.

### 3.5 정보 위계와 상태 표현

- 질문에서 수량과 단위는 색상만이 아니라 굵기와 밑줄 또는 배지로 구분한다.
- 문제 아이콘은 장식이 아니라 문장의 “묶음 수, 묶음당 개수, 추가 수량”을 표현한다.
- 보드의 봉인 조각은 숫자, 연산자, 괄호 유형을 서로 다른 윤곽으로 표시하되 실제 값은 발굴 전까지 감춘다.
- 수식 패널은 `빈 수식 슬롯`, `발굴 조각 보관함`, `검증 피드백` 순서로 배치한다.
- 색약 사용자를 위해 모든 매치 타일은 색상과 함께 도형·문양을 가진다.
- 애니메이션 감소 설정에서는 흔들림·입자·확대 연출을 정적 강조로 대체한다.

## 4. 핵심 게임 루프

### 4.1 1단계: 문제 해석

스테이지 시작 시 질문과 상황 아이콘을 먼저 1초 이상 안정적으로 보여준다. 플레이어는 즉시 보드를 조작할 수 있지만, 필요한 관계를 추측할 수 있도록 다음 정보를 제공한다.

- 무엇을 구하는지 나타내는 목표 단위
- 수식에 들어갈 총 조각 수의 범위 또는 빈 슬롯 수
- 초급에서는 필요한 조각 유형 수: 숫자 3개, 연산자 2개 등
- 중급 이상에서는 조각 유형 힌트를 감추고 질문만으로 판단하게 한다.

빈 슬롯 수는 수식 길이에 대한 힌트이므로 난도 옵션으로 관리한다. 하나의 정답 형태만 강요하지 않는 문제는 고정 슬롯 대신 가변 수식 줄을 사용한다.

### 4.2 2단계: 수식 조각 발굴

보드의 일반 타일은 색상뿐 아니라 원, 삼각, 사각, 별, 물결 같은 문양으로 구분한다. 인접한 두 타일을 교환해 같은 문양을 가로 또는 세로로 3개 이상 연결하면 제거된다.

보드에는 “봉인된 수식 조각”이 섞여 있다.

- 일반 매치를 봉인 주변에서 만들면 봉인이 한 단계 깨진다.
- 봉인 단계는 초급 1회, 일반 1~2회, 도전 2~3회다.
- 봉인이 완전히 깨지면 내부의 숫자·연산자·괄호가 발굴된다.
- 발굴된 조각은 화면을 가로지르는 긴 연출 없이 바로 수식 패널 보관함으로 이동한다.
- 필수 조각이 아닌 보너스·방해 조각도 일부 존재할 수 있지만, 초반에는 사용하지 않는다.

플레이어가 문장을 읽고 필요한 기호를 예상할 이유를 만들기 위해 봉인 외곽에 유형을 표시한다.

- 원형 봉인: 숫자
- 마름모 봉인: 연산자
- 쌍문 봉인: 괄호 한 쌍

초급에서는 봉인 위에 `숫자`, `연산` 라벨을 함께 표시한다. 중급에서는 윤곽만 제공한다. 고급에서는 일부 봉인이 미확인 상태이며, 관찰용 특수 매치로 유형부터 판별한다.

### 4.3 3단계: 식 구성

발굴한 조각은 즉시 보관함에서 선택할 수 있다. 플레이어는 매치 퍼즐을 끝낸 뒤에만 식을 만드는 것이 아니라, 발굴과 조립을 오가며 가설을 수정한다.

- 보관함 조각을 탭하거나 드래그해 수식 줄에 넣는다.
- 같은 숫자나 기호가 여러 개여도 각각 고유한 조각 ID를 유지한다.
- 수식 줄에서 탭하면 보관함으로 돌아간다.
- 길게 누르기 또는 드래그로 순서를 바꾼다.
- 되돌리기는 최근 매치가 아니라 수식 편집만 되돌린다. 매치 이동 취소는 부정행위와 상태 복잡성을 피하기 위해 기본 제공하지 않는다.
- 아직 발굴되지 않은 필수 조각은 반투명 정답으로 노출하지 않고 “숫자 조각 1개 남음”처럼 유형만 표시한다.

### 4.4 4단계: 검증과 완료

확인 버튼은 최소 하나의 완전한 식을 구성했을 때 활성화한다.

검증 순서:

1. 조각 소유권과 중복 ID 확인
2. 괄호와 연산자 위치를 포함한 문법 검사
3. 정확한 유리수 계산
4. 문제의 교육 목표 AST 또는 허용된 동치식 확인
5. 목표 단위와 계산 결과 확인

오답은 발굴 조각이나 이동 수를 소모하지 않는다. 다음처럼 원인에 맞는 피드백을 제공한다.

- 문법 오류: “연산자 뒤에는 수가 필요해요.”
- 값은 같지만 관계가 다름: “답은 같지만 ‘3묶음’을 나타내는 곱셈이 빠졌어요.”
- 계산 오류: 첫 번째 잘못된 계산 구간을 강조한다.
- 미사용 필수 조각: 필요한 유형과 남은 수만 알려준다.

정답이면 질문의 수량과 수식 블록을 같은 강조색과 선으로 1:1 연결한 뒤, 한 문장 설명을 보여준다. 설명 확인 후 보상 화면과 다음 스테이지로 진행한다.

## 5. 매치 보드 세부 규칙

### 5.1 기본 보드

- 기본: 6×6, 일반 타일 5~6종, 봉인 3~7개
- compact-safe 폴백: 5×5, 일반 타일 5종, 봉인 2~5개
- 한 판 이동 수: 초급 10~14회, 일반 12~18회, 도전 16~24회
- 초기 보드는 즉시 성립한 매치가 없고, 최소 하나 이상의 유효 교환이 있어야 한다.
- 유효 교환이 없으면 이동 수 차감 없이 자동 섞기한다.
- 자동 섞기 후에도 필수 봉인이 도달 불가능하면 같은 seed의 보드 재생성이 아니라 검증된 대체 상태로 전환한다.

### 5.2 특수 타일

특수 타일은 조작 설명이 필요한 새로운 규칙이므로 한 번에 하나씩 도입한다.

| 생성 조건 | 결과 | 학습 연결 |
| --- | --- | --- |
| 4개 직선 연결 | 행 또는 열 복원 타일 | 멀리 있는 봉인을 계획적으로 타격 |
| ㄱ·ㅗ 형태 5개 연결 | 주변 3×3 복원 타일 | 여러 조각을 함께 발굴 |
| 5개 직선 연결 | 같은 문양 전체 제거 | 특정 봉인 경로 확보 |

특수 타일끼리 결합하는 복잡한 조합은 P0 범위에서 제외한다. 연쇄는 만족감을 주되, 화면을 가리고 2초 이상 조작을 막는 연출은 사용하지 않는다.

### 5.3 봉인 배치와 공정성

필수 정답 조각은 콘텐츠 생성 시 `requiredTokenPlan`에 등록한다. 보드 생성기는 각 필수 조각을 다음 조건으로 배치한다.

- 첫 3회 이동 안에 최소 하나의 조각을 발굴할 수 있다.
- 필수 조각이 서로를 영구적으로 가로막지 않는다.
- 현재 이동 수로 모든 필수 조각을 발굴할 수 있는 검증 경로가 존재한다.
- 연쇄 결과가 달라져도 필수 조각이 파괴되거나 보드 밖으로 사라지지 않는다.
- 괄호 한 쌍은 한 봉인에서 함께 나오거나 각각의 위치가 명확히 표시된다.

필수 조각을 일반 낙하 확률에 맡기지 않는다. 무작위성은 타일 배열과 연쇄에 사용하되, 스테이지 완료 가능성은 결정론적으로 보장한다.

### 5.4 방해 조각과 장애물

방해 조각은 수학적 판단을 만들 때만 사용한다.

- 초급: 정답 조각만 제공한다.
- 일반: 숫자 또는 연산자 방해 조각 1~2개를 추가한다.
- 고급: 값은 같지만 문장 관계와 맞지 않는 식을 유도하는 조각을 추가한다.

얼음, 사슬 같은 일반적인 장애물은 시각 테마에 맞춰 `먼지`, `금이 간 석판`, `잠금 룬`으로 재해석한다. 장애물 종류를 늘려 난도를 만드는 방식보다 봉인 접근 경로와 수식 판단을 결합하는 방식을 우선한다.

## 6. 재미를 만드는 구조

### 6.1 의미 있는 선택

매치가 가능한 곳을 아무 데나 누르는 플레이를 줄이기 위해 각 봉인 주변에 요구 문양을 표시할 수 있다. 예를 들어 삼각 문양을 주변에서 매치해야 숫자 봉인이 깨진다. 플레이어는 질문을 읽고 먼저 필요한 것으로 보이는 조각의 경로를 선택한다.

### 6.2 짧은 보상 주기

- 한 번의 매치: 명확한 타격·진행 표시
- 2~4번의 매치: 첫 조각 발굴
- 판 중반: 부분 식 구성
- 판 후반: 마지막 조각과 식 완성
- 스테이지 완료: 관계 설명, 별, 컬렉션 진행

### 6.3 연쇄와 수학의 연결

연쇄 자체의 점수보다 발굴 효율을 보상한다. 한 연쇄로 여러 봉인을 타격하면 `연결 발견` 보너스를 주고, 질문에서 연관된 수량을 올바른 순서로 배치하면 `관계 발견` 피드백을 준다. 단순한 고득점 경쟁이 학습 목표를 밀어내지 않도록 최고 점수는 보조 지표로 둔다.

### 6.4 반복 플레이 변화

같은 문제 템플릿이라도 숫자, 상황 아이콘, 보드 seed, 봉인 위치가 달라질 수 있다. 그러나 정답 조각 종류와 이동 수가 바뀔 때는 자동 풀이 검증을 다시 통과해야 한다. 일일 도전은 기존 문제의 숫자만 크게 만드는 대신 다음 중 하나를 바꾼다.

- 더 적은 이동으로 발굴
- 방해 조각 중 올바른 관계 선택
- 괄호가 필요한 식 구성
- 서로 다른 두 동치식 중 문장에 더 직접적인 식 선택

## 7. 학습 설계

### 7.1 매치와 수학의 역할 분리

매치 퍼즐은 집중과 발굴의 재미를 담당하고, 수식 조립은 학습 목표를 담당한다. 매치 난도가 높아 수학을 시도조차 못 하는 상황을 피한다. 학습 진단 점수는 매치 실력과 분리해 기록한다.

- discoveryMastery: 이동 효율, 특수 타일 사용, 봉인 발굴
- mathMastery: 문장 관계 해석, 첫 제출 정확도, 힌트 단계

### 7.2 단계형 힌트

힌트는 다음 순서로 제공한다.

1. 문장 강조: 관련 수량과 단위를 강조한다.
2. 관계 힌트: “같은 수가 여러 묶음이면 어떤 연산일까요?”
3. 조각 유형: 필요한 연산자 또는 괄호 유형을 알려준다.
4. 보드 힌트: 해당 봉인에 도달하는 유효 교환 하나를 표시한다.
5. 부분 식: 수식의 한 구간만 고정한다.

매치 힌트와 수학 힌트를 별도 버튼으로 나누지 않고, 현재 막힘 상태를 기준으로 가장 작은 도움부터 제공한다. 8초 동안 유효 입력이 없으면 선택 가능한 매치만 은은하게 표시하고, 정답 식은 자동 노출하지 않는다.

### 7.3 오답 학습

- 첫 오답은 현재 식을 보존하고 원인만 설명한다.
- 같은 유형의 두 번째 오답은 문장 속 해당 구간과 수식 구간을 연결한다.
- 세 번째 오답은 부분 식 또는 조작 가능한 예시를 제공한다.
- 정답 후에는 “왜 이 연산인가”를 1문장으로 요약한다.
- 다음 문제에서는 직전 오답 유형을 한 번만 낮은 난도로 재확인한다.

## 8. 난이도 설계

수학 난도와 매치 난도를 별도 축으로 관리한다. 두 축을 같은 스테이지에서 동시에 크게 올리지 않는다.

### 8.1 수학 난도 축

1. 숫자 두 개와 연산자 하나
2. 숫자 세 개와 연산자 두 개
3. 연산 우선순위
4. 괄호
5. 같은 숫자·연산자 중복
6. 단위 변환, 분수, 소수
7. 방해 조각과 허용 동치식

### 8.2 매치 난도 축

1. 5×5 보드와 5문양, 1단계 봉인
2. 봉인 위치 선택
3. 2단계 봉인
4. 한 종류의 장애물
5. 특수 타일 사용 요구
6. 이동 수 최적화

### 8.3 권장 진행 단위

한 학습 묶음은 8~10스테이지로 구성한다.

1. 새 수학 개념 안내
2. 매치 규칙이 쉬운 개념 연습
3. 숫자 변화
4. 첫 방해 조각
5. 수식 구조 변화
6. 매치 경로 선택
7. 혼합 복습
8. 개념 확인 스테이지

개념 확인 스테이지는 매치 이동 수를 과도하게 줄이지 않는다. 학습 숙련도는 첫 제출과 힌트 사용을 중심으로 평가한다.

## 9. 실패 방지와 복구

### 9.1 불가능한 보드 방지

- stageId, problemSeed, boardSeed를 저장해 모든 판을 재현한다.
- 생성 직후 유효 이동, 필수 봉인 도달 가능성, 최소 예상 이동 수를 검사한다.
- 최소 예상 이동 수에 난도별 여유 계수를 더해 이동 수를 배정한다.
- 플레이 중 유효 교환이 없으면 무료 섞기를 실행한다.
- RNG 결과로 필수 조각이 유실되는 규칙은 만들지 않는다.

### 9.2 이동 수 소진

이동 수가 0이 되면 즉시 생명이나 재화를 요구하지 않는다.

- 마지막 필수 조각까지 예상 1~2회 이동이면 1회에 한해 `집중 기회` 2회를 제공한다.
- 실패해도 이미 확인한 조각 유형과 수학 힌트 단계는 같은 스테이지 재도전에서 유지할 수 있다.
- 무료 재도전은 새로 검증된 boardSeed를 사용한다.
- 수식 오답은 이동 수에 영향을 주지 않는다.
- 아동 대상 기본 경로에는 대기 시간형 생명 시스템을 두지 않는다.

### 9.3 조작 실수 방지

- 매치가 만들어지지 않는 교환은 이동 수를 차감하지 않고 원위치한다.
- 확인 전 수식 조각을 자유롭게 되돌릴 수 있다.
- 수식 초기화에는 즉시 실행 후 되돌리기 또는 짧은 확인 절차를 둔다.
- 앱이 중단되면 보드, 이동 수, 발굴 조각, 현재 식, seed를 함께 복원한다.

## 10. 보상과 진행

### 10.1 별 평가

별은 최대 3개이며 한 기준이 다른 기준을 완전히 가리지 않게 구성한다.

- 기본 별 1개: 스테이지 완료
- 수학 별 1개: 첫 제출 정답 또는 낮은 단계 힌트만 사용
- 탐색 별 1개: 난도별 기준 이동 수 안에 발굴 완료

힌트를 사용해도 완료 별은 잃지 않는다. 최고 기록은 재도전으로 갱신할 수 있다. 캐릭터나 장식 구매로 학습 경로가 막히지 않도록 누적 별과 소비 재화를 분리한다.

### 10.2 장기 보상

- 개념 지도: 곱셈, 나눗셈, 괄호 등 숙련 노드 개방
- 수식 도감: 배운 관계와 대표 예시 수집
- 유적 복원: 플레이로 배경·기념물을 단계적으로 복원
- 캐릭터 반응: 정답 설명과 짧은 응원, 능력치 우위 없음
- 주간 복습: 취약 개념 3개를 짧게 재구성

무작위 유료 뽑기, 정답 조각 판매, 실패 직후 압박 결제는 사용하지 않는다. 보상은 학습 진행과 꾸미기 중심으로 설계한다.

## 11. 튜토리얼 순서

튜토리얼은 설명 팝업을 연속으로 보여주지 않고, 한 판에 새 규칙 하나만 추가한다.

| 단계 | 수학 목표 | 새 조작 | 완료 조건 |
| --- | --- | --- | --- |
| T1 | 두 수의 덧셈 | 표시된 교환 1회, 숫자 봉인 발굴 | `3+2` 조립 |
| T2 | 묶음과 곱셈 | 자유 매치, 연산자 봉인 | `4×3` 조립 |
| T3 | 두 단계 식 | 여러 봉인 중 목표 선택 | `4×3+2` 조립 |
| T4 | 수식 수정 | 조각 제거·재정렬·되돌리기 | 잘못 놓인 식 수정 |
| T5 | 괄호 | 쌍문 봉인과 괄호 한 쌍 | `2×(7+5)` 조립 |
| T6 | 효율적 발굴 | 4개 매치 특수 타일 | 기준 이동 수 안에 완료 |
| T7 | 관계 구분 | 방해 조각 1개 | 값뿐 아니라 문장에 맞는 식 제출 |

각 단계는 손가락 애니메이션을 한 번만 제공한다. 두 번 실패하면 해당 조작을 다시 표시하고, 성공 후에는 강제 안내를 종료한다. 튜토리얼 완료 여부와 개별 규칙 이해 여부를 별도로 저장해 필요한 규칙만 다시 안내한다.

## 12. 콘텐츠와 보드 생성

### 12.1 콘텐츠 스키마 추가 필드

기존 `PuzzleTemplate`에 다음 발견 퍼즐 필드를 추가한다.

- discoveryModeVersion
- requiredTokenPlan
- optionalTokenPlan
- sealTypeByToken
- boardWidth, boardHeight
- tileKinds
- obstaclePlan
- specialTileRules
- moveBudgetRule
- boardDifficulty
- boardSeedPolicy
- revealOrderPolicy
- compactLayoutVariant
- tutorialRuleId

`requiredTokenPlan`은 정답 문자열이 아니라 고유 token instance와 정답 AST의 대응을 가진다. 동치식을 허용할 때는 모든 허용식의 조각 합집합을 무조건 보드에 넣지 않고, 스테이지가 제공할 풀이 경로를 먼저 선택해 해당 멀티셋을 생성한다.

### 12.2 생성 절차

1. 문제 템플릿과 problemSeed로 변수 값을 생성한다.
2. 정답 AST와 필요한 token instance 멀티셋을 만든다.
3. 난도에 따라 시작 제공 조각, 봉인 조각, 선택 방해 조각을 나눈다.
4. 보드 크기, 문양 수, 봉인 위치, 장애물을 boardSeed로 배치한다.
5. 초기 자동 매치를 제거하고 최소 하나의 유효 교환을 보장한다.
6. 제한된 자동 플레이 또는 역생성 방식으로 모든 필수 봉인의 도달 가능성을 확인한다.
7. 예상 최소 이동 수와 이동 예산을 비교한다.
8. 실패하면 정해진 횟수만 새 boardSeed를 시도하고, 이후 검증된 fallback 보드를 사용한다.
9. problemSeed, boardSeed, contentVersion, 생성 변수를 세션에 저장한다.

### 12.3 자동 검증

활성 템플릿은 다음을 통과해야 한다.

- 정답 AST를 requiredTokenPlan으로 구성할 수 있다.
- 같은 표시값 조각의 수량과 ID가 보존된다.
- compact 5×5 보드에서도 필수 조각이 모두 배치된다.
- 모든 필수 봉인에 도달 가능한 경로가 있다.
- 시작 상태와 자동 섞기 후 상태에 유효 이동이 있다.
- 지정 이동 수 안에 최소 하나의 자동 풀이 표본이 성공한다.
- 방해 조각만으로도 우연히 허용되지 않은 값-동일 식을 만들 수 있는지 검사한다.
- 1,000개 이상의 problemSeed·boardSeed 조합에서 예외, 빈 보드, 미발굴 필수 조각이 없다.
- 실패 seed를 회귀 fixture로 저장한다.

자동 플레이는 최적 플레이를 완전히 증명하는 도구가 아니라 명백한 불가능 보드를 제거하는 1차 필터다. 활성 승격 전에는 대표 seed의 사람 플레이 검증을 추가한다.

## 13. 샘플 vertical slice

첫 구현은 기존 샘플 문제 `상자 3개에 연필이 각각 4자루씩 있고, 낱개 2자루가 더 있다`를 사용한다.

- 목표 식: `4×3+2`
- 목표값: 14
- 기본 보드: 스마트폰 저높이 5×5, 높이 400dp 이상 6×6, 문양 5종
- compact-safe 폴백: 5×5, 문양 5종과 폴백 전용 검증 seed
- 필수 봉인: `4`, `×`, `3`, `+`, `2`
- 시작 제공 방식: 첫 실행에서는 `4`, `3`을 제공하고 `×`, `+`, `2`를 발굴한다.
- 다음 난도에서는 다섯 조각을 모두 발굴한다.
- 이동 수: 현재 P0 fixture 12회
- 봉인 내구도: 1회
- 특수 타일: P0에서는 없음, P1에서 4개 직선 연결 1종 추가
- 방해 조각: P0에서는 없음

현재 구현 fixture는 첫째 줄, 셋째 줄, 넷째 줄에서 각각 한 번의 의도된 교환을 수행해 `×`, `+`, `2`를 순서대로 한 개씩 발굴한다. 5×5·6×6은 독립 fixture ID와 seed를 가지며, 순수 Dart verifier가 양쪽에서 같은 세 교환, 이동 수 감소, 발굴 순서, 세 번째 교환에서만 완료되는 조건을 재생한다. 첫 튜토리얼에서는 안내된 교환만 허용해 고정 안내와 실제 보드가 어긋나지 않게 한다. 이는 조작과 학습 루프를 확인하기 위한 튜토리얼 fixture이며 일반 스테이지의 최종 난도는 아니다.

한 화면에서 질문·상자 3개 도식·5×5 보드·발굴 보관함·수식 줄·확인 버튼이 동시에 보여야 한다. 높이 400dp 이상에서만 6×6으로 확장한다. 플레이어는 매치 도중 `4×3`을 먼저 구성하고, 마지막 `+2`를 발굴한 뒤 식을 완성할 수 있어야 한다.

## 14. 기술·성능·접근성 기준

### 14.1 렌더링과 상태 분리

- 문제/수식 상태와 매치 보드 상태를 별도 controller로 관리한다.
- 보드의 한 타일 변경으로 질문 패널 전체가 rebuild되지 않게 한다.
- 보드와 큰 배경 애니메이션은 별도 `RepaintBoundary`로 분리한다.
- 타일 스프라이트는 작은 atlas 또는 캐시된 벡터/래스터를 사용한다.
- 파티클을 풀링하고 동시 표시 수를 제한한다.
- 발굴 연출 중에도 질문과 수식 조작을 불필요하게 잠그지 않는다.
- 게임 규칙은 프레임 시간이나 애니메이션 완료 콜백에 의존하지 않는다.

### 14.2 성능 목표

- FHD Android 실기기 profile/release 모드에서 목표 60fps
- 일반 교환·낙하 중 지속적인 16.7ms 초과 프레임이 없어야 함
- 연쇄 시 50ms 이상의 멈춤이 반복되지 않아야 함
- 화면 회전·백그라운드 복귀 후 세션과 보드가 정확히 복원되어야 함
- compact 화면에서 텍스트 잘림, RenderFlex overflow, 수식 버튼 가림이 없어야 함

수치는 실제 저·중급 FHD 기기에서 DevTools profile로 측정하며, 디버그 모드 프레임을 출시 성능 판단에 사용하지 않는다.

### 14.3 접근성

- 타일은 색상 외에 도형과 패턴을 가진다.
- 선택한 타일의 행·열과 문양을 Semantics로 읽는다.
- 교환 조작은 드래그 외에 선택 후 방향 버튼 또는 두 타일 연속 선택으로도 가능해야 한다.
- 발굴 조각은 `숫자 4`, `곱하기`, `왼쪽 괄호`처럼 읽는다.
- 상태 변화는 “곱하기 조각을 발굴했습니다. 숫자 조각 1개 남음”처럼 짧게 알린다.
- 화면 흔들림, 섬광, 햅틱, 입자 효과를 각각 줄이거나 끌 수 있다.

## 15. 분석 이벤트와 난도 조정

개인 식별 정보 없이 로컬 또는 승인된 분석 계층에 다음 이벤트를 기록할 수 있다.

- stage_started: templateId, 두 seed, 난도
- seal_revealed: token type, 사용 이동 수
- equation_submitted: 오류 분류, 힌트 단계, 제출 횟수
- stage_failed: 남은 필수 조각, 보드 상태 해시
- stage_completed: discoveryMastery, mathMastery, 소요 시간
- shuffle_triggered: 자동 섞기 원인

문장 원문, 자유 입력, 사용자 이름은 이벤트에 포함하지 않는다. 난도 조정은 완료율 하나로 판단하지 않고 첫 발굴까지의 이동 수, 마지막 조각에서의 실패, 첫 제출 정확도를 함께 본다.

## 16. 단계별 구현 계획

### P0: 통합 vertical slice

- 초광폭 스마트폰 5×5 보드와 높이 400dp 이상 6×6 확장
- 인접 교환과 3개 이상 매치
- 낙하·보충·자동 섞기
- 1단계 봉인과 필수 조각 발굴
- 기존 수식 엔진·보관함·정답 검증 연결
- `4×3+2` 고정 fixture
- 질문·아이콘·보드·수식 한 화면 레이아웃
- 기본 힌트, 이동 수 소진, 무료 재도전
- initial, mid-match, token-reveal, composing, incorrect, correct 고정 화면 상태

### P1: 규칙과 콘텐츠 확장

- 6×6 보드의 추가 레이아웃 tier와 보드 규칙 확장
- 2단계 봉인, 4개 매치 특수 타일
- 5개 수학 샘플 전체 연결
- seed 기반 생성·세션 복원
- 수학/매치 난도 분리
- 첫 7단계 튜토리얼
- 키보드·스크린리더 대체 조작

### P2: 반복 플레이 구조

- 활성 47개 템플릿의 discovery 설정
- 장애물 1~2종과 방해 조각
- 개념 지도, 수식 도감, 유적 복원 보상
- 적응형 복습과 힌트
- 실기기 성능·접근성 검증

복잡한 특수 타일 조합, 경쟁 순위, 이벤트 라이브 운영은 핵심 루프의 학습 효과와 유지율을 검증한 뒤에만 추가한다.

## 17. 완료 기준

### P0 기능 완료

- 800×360·720×320 및 SafeArea 후 680×300에서 질문, 상황 도식, 이동 수, 5×5 보드, 발굴 조각, 수식 줄, 확인 버튼이 3영역으로 나뉘어 스크롤 없이 동시에 보인다.
- compact-safe 조건에서는 같은 정보 위계를 유지한 5×5 폴백 보드로 전환된다.
- 인접 교환, 매치, 낙하, 보충이 같은 seed에서 재현된다.
- 유효하지 않은 교환은 이동 수를 쓰지 않는다.
- 유효 이동이 없을 때 무료 자동 섞기가 작동한다.
- 필수 세 조각을 발굴해 `4×3+2`를 완성할 수 있다.
- 발굴 중에도 이미 얻은 조각으로 부분 식을 만들 수 있다.
- 오답이 보드 진행과 발굴 조각을 삭제하지 않는다.
- 앱 중단 후 보드와 식이 함께 복원된다.

### P0 품질 완료

- 1,000개 boardSeed 자동 생성 검사에서 빈 보드, 초기 불능, 필수 조각 유실이 없다.
- domain 테스트가 매치 판정, 연쇄, 봉인 타격, 이동 수, 재현 seed를 검증한다.
- 수식 테스트가 중복 조각, AST, 동치값-비동치관계, 괄호를 검증한다.
- 800×360, 720×320, 680×300, 640×360, 960×432 golden에서 overflow와 핵심 요소 가림이 없다.
- 실제 FHD Android 기기에서 한 판을 처음부터 끝까지 플레이한다.
- profile/release 성능 측정에서 지속적인 프레임 저하가 없다.
- 색상 없이도 타일과 봉인 유형을 구별할 수 있다.
- 스크린리더 또는 대체 선택 조작으로 한 판을 완료할 수 있다.

### 게임성 검증 완료

소규모 플레이 테스트에서 다음을 확인한다.

- 처음 플레이한 사용자가 2분 안에 `매치 → 조각 발굴 → 식 조립`의 관계를 설명할 수 있다.
- 튜토리얼 완료 사용자의 80% 이상이 별도 설명 없이 첫 일반 스테이지를 완료한다.
- 실패 원인의 다수가 보드 운이 아니라 판단 또는 학습 가능한 조작으로 설명된다.
- 플레이어가 질문을 읽지 않고 무작위 매치만 반복해도 항상 성공하는 구조가 아니다.
- 매치 숙련도가 낮은 사용자의 수학 시도 기회가 차단되지 않는다.

이 기준을 만족한 뒤에만 전체 월드맵, 캐릭터, 뱃지, 303개 콘텐츠 이식으로 범위를 넓힌다.
